# Randomized-compiling assumption table

**Status:** full-text reading note, 2026-11-20. This table interprets
Wallman--Emerson (2016) and Winick et al. (2022) for the proposed project. It is
not a proof that the proposed QAOA construction satisfies their assumptions.

Primary texts:

- J. J. Wallman and J. Emerson, *Noise tailoring for scalable quantum
  computation via randomized compiling*, PRA 94, 052325 (2016), arXiv v3.
- A. Winick et al., *Concepts and conditions for error suppression through
  randomized compiling*, arXiv:2212.07500.

## Assumption and scope table

| Item | Wallman--Emerson result | Winick extension/qualification | Status for this project |
|---|---|---|---|
| Cycle form | Bare circuit is reorganized into easy-gate rounds `C_k` followed by hard-gate rounds `G_k`. | Uses the same canonical cycle form. | **Open.** The cost `RZ` must be classified consistently; calling it easy or hard changes which guarantee is relevant. |
| Twirl set | `T` must twirl an arbitrary channel to a stochastic channel; Pauli twirls are canonical. | Uses local Pauli twirls/unitary 1-designs. | Plausible for Pauli labels, but the exact label set and boundary treatment are not yet frozen. |
| Correction closure | `T_k^c = G_k T_k^dagger G_k^dagger` must lie in the group generated by easy gates so that correction and twirl can be compiled into one dressed easy round. | Same requirement; examples use arbitrary local `SU(2)` easy gates with CNOT hard gates. | **Unproved.** Must be checked for the actual QAOA decomposition, not inferred from `X RZ(theta) X = RZ(-theta)`. |
| Logical equivalence | Every randomized circuit implements the same ideal logical circuit after corrections. | Same. | Required semantic test for every label pattern. |
| Sampling | Twirls are independently sampled in each round; the tailored channel is an average over random compilations, not the channel of a single randomized circuit. | Separates the single-randomization decoupling effect from the many-randomization tailoring effect. | The project must not call one labeled circuit a Pauli-tailored channel. Shot/circuit allocation must specify what is independently randomized. |
| Hard-gate noise | Exact Markovian tailoring tolerates arbitrary dependence on the hard gate, provided the easy-gate noise is gate independent. | Repeats this boundary. | If the cost rotation and E2 are assigned to a hard gate, correction closure and physical implementation still need proof. |
| Easy-gate noise | The exact theorem assumes gate-independent easy-gate noise. Gate dependence is handled by a diamond-norm difference between the real circuit and an averaged gate-independent surrogate, not by an exact tailoring identity. | Emphasizes that realistic easy-gate control errors violate the exact assumption; the additional error grows with depth and is small only under the stated bounds. | **Central mismatch.** If label absorption changes the implemented `RZ` angle and E2 depends on that angle, the easy-gate error is label/gate dependent. This is not covered by the exact theorem. |
| Normalization condition | A stronger gate-dependent bound is available when the twirling group is normalized by the easy-gate group. | Uses the same condition. | Must be checked after the dressed-gate set is frozen. It does not by itself create information about `epsilon`. |
| Markovianity | Main exact theorem is for Markovian cycle noise; the original paper left long-memory noise open. | Extends tailoring to time-dependent Markovian errors and to local stochastic Pauli noise for a persistent environment, still with gate-independent easy-gate errors. | Not needed for the first noiseless Gate 1 check, but relevant before noisy claims. |
| Gate-dependent non-Markovian noise | Not covered by the exact result. | Gives an adversarial failure mechanism: the environment can preserve coherent accumulation if gate-dependent errors reveal enough twirl-parity information. | Later noisy models must state whether labels can leak into the environment/control error. No universal suppression claim is allowed. |
| Error metric | Tailoring can greatly improve nonlinear worst-case metrics while average infidelity is unchanged by averaging. | Explicitly separates linear and nonlinear metrics and the single/many-randomization effects. | The project endpoint is decision loss, so a channel-level improvement cannot be used as a proxy for decision improvement. |
| Label retention | Labels are compiler bookkeeping used to form dressed gates; the papers analyze averaged noise, not estimation from label--outcome correlation. | Does not establish the Vyas estimator or identify `epsilon`. | Gate 1 identifiability requires a separate likelihood argument. |

## Consequences for Gate 1

1. **RC suppression and RC-label sensing are different propositions.** These
   papers can justify an averaged-channel statement only when their assumptions
   hold. They do not imply that a retained label identifies a parameter.
2. **E2 cannot be placed silently on the convenient side of the easy/hard
   split.** If it is easy-gate noise, its angle dependence threatens exact
   tailoring. If it is hard-gate noise, the correction group and actual
   decomposition still have to close.
3. **Gate 1A must test the implemented dressed circuit.** Algebraic frame
   identities, circuit equivalence, conditional likelihood, and the absence of
   target-ideal inputs are separate checks.
4. **A negative Gate 1A result does not contradict RC.** It can mean that RC
   still tailors some averaged error while the chosen label contrast carries no
   deployable information about logical-angle `epsilon`.

## Required pre-simulation checks

- Freeze `C`, `G`, `T`, every `T_k^c`, and the boundary-cycle convention.
- Enumerate the physical/dressed `RZ` angle for every label.
- State whether E2 is a channel after a fixed ideal gate or a gate-dependent
  implementation rule.
- Verify logical equivalence without noise for every label pattern.
- Derive `P(b | s, epsilon, phi)` from the implemented circuit; do not import a
  sign model from a different construction.
- Report results separately for one randomization and an average over
  randomizations.
