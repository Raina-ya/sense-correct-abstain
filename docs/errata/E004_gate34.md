# Erratum E004 — Gates 3 and 4 (2026-11-21)

**Affected frozen artifacts (unchanged):** `docs/freeze/gate3_gate4_design.md`,
`tools/run_gate34.py`, `src/sense_correct_abstain/gate34.py`,
`results/gate34/gate34_results.json`, `docs/results/gate3_gate4_report.md`,
`docs/freeze/power_analysis.md`.

**Frozen verdicts:** Gate 3 FAIL, Gate 4 PASS, route Stop-after-M6.
**Status:** both verdicts **stand**. Gate 3 FAIL is robust to the corrected
estimand (§1). The route to MT7 synthesis is unchanged.

## 1. Selection-conditioning defect in the policy's N-path loss

The frozen policy chooses N only when the realized initial gap satisfies
`|g0_hat| > 1.96 * SE_g0`. On path N it issues `delta_0 = sign(g0_hat)` from
those same shots.

The runner nevertheless scored the policy's N loss as
`1 - sensor_correct_probability`. That is an unconditional probability, from
256 independent replicate redraws, of the always-issue decision. In general
`E[1{N} * that probability] != E[1{N} * 1{delta_0 wrong}]`, so the frozen
`Delta_V` estimates a different quantity from the policy's expected loss. The
loss conditional on the stage-1 data is `1{delta_0 wrong}` (theory note,
Theorem T1, `l_N`).

**POST-HOC corrected-estimand reanalysis.** `tools/audit_gate34_estimand.py` →
`results/errata/gate34_estimand.json`. It changes only the N-path loss, to the
realized indicator. It keeps the frozen comparator (C-always, selected on the
policy-lock partition), the C and A losses, and the frozen cluster bootstrap
(same seed and quantile rule).

As a fidelity check, the script first reproduces the frozen values exactly.

| Quantity | Frozen | Corrected estimand |
|---|---:|---:|
| `Delta_V` | 0.0000804 | 0.0002369 |
| One-sided 95% cluster-bootstrap lower bound | −0.000743 | −0.000625 |
| Gate 3 decision under the frozen rule | FAIL | would also FAIL |
| Mean N-path loss (919 units) | 0.00278 (unconditional) | 0.00218 (realized) |

On C units the policy loss equals the selected C-always comparator loss
exactly, so `Delta_V` is driven entirely by the 27% of units where the policy
chose N or A. The corrected estimand cannot rescue Gate 3. It would not
authorize M7 even if its bound had been positive, because it was specified
after the result.

## 2. Monte Carlo scoring

All action losses are 256-replicate Monte Carlo estimates of selection
probabilities. The stored per-unit losses have granularity `1/256`, which is
coarse relative to `|Delta_V| < 0.001`. Exact selection probabilities were
computable.

## 3. Power was assessed in the same run as the evaluation

The lock (§7) placed the power analysis "after fixed-comparator selection but
before inspecting evaluation outcomes". The runner computed both in one
execution, so no decision point existed between them.

The estimated power was **0.0004**: the minimum detectable mean was 0.000665,
while the mean of the 33 policy-lock cluster means of `Delta_u` was −0.00063. The Gate 3 test
therefore had essentially no chance of passing. Had power been inspected
first, the design could have been revised before any evaluation outcome
existed.

## 4. Gate 4 thresholds were not derived from power analysis

The program plan asks for a minimum action frequency "supported by power
analysis". The lock fixed 5% of units and 10 of 66 clusters a priori, which is
a deviation. Gate 4 passed: N 25.9%, C 72.6%, A 1.5% (A did not clear). It is
moot after the Gate 3 failure.

## 5. Reproducibility

A full recomputation with NumPy 2.3.5 (the version recorded in the artifact)
on Linux found 31 of 5940 units differing in stored floats (Monte Carlo
probabilities): 25 in the evaluation partition and 6 in the policy-lock
partition. These come from last-bit platform differences in the input
probabilities. No action differs, and the comparator selection is unchanged.

The Gate 3 `Delta_V` and lower bound computed from the recomputed rows are
**identical** to the frozen values. In every differing evaluation unit, the
change cancels inside `Delta_u`: either the policy chose C, so its loss and the
C-always comparator loss share the same corrected-rerun probability, or the
change is in a field that does not enter `Delta_u` (E005).

## 6. Consequence

> Under the frozen synthetic model and budget, the deployable three-action
> policy shows no detectable net value over the best fixed policy
> (always correct). The design had essentially no power to detect one.

This is the resource/value boundary result that MT7 must report. The policy
coincides with always-correct on 73% of units.
